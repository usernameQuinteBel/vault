# Low-code

> Software bouwen door vooral visueel te werken (slepen, configureren, formules) in plaats van alles zelf te programmeren. De Power Platform ondersteunt no code, low code én code first naast elkaar.

## De drie niveaus
| Niveau | Hoe | Voor wie |
|---|---|---|
| **No code** | Volledig drag-and-drop | [[Citizen developer]]s / power users |
| **Low code** | Drag-and-drop + wat formules/code voor extra functionaliteit | IT-developers, gevorderde makers |
| **Code first** | Professionele ontwikkeling, eigen componenten en API's, uitbreiden via [[Azure]] | Pro developers |

Het sterke punt: deze drie groepen werken op **hetzelfde platform** samen. Een citizen developer bouwt de app, een pro developer voegt een custom component of connector toe, en iedereen kan die hergebruiken ("no cliffs": je loopt niet tegen een muur als je meer nodig hebt).

## Voordelen
- Veel snellere oplevering ("uren in plaats van maanden").
- Lagere ontwikkelkost.
- **Build with, not for, the business**: gebruikers geven live input en passen zelf mee aan.
- Minder afhankelijk van moeilijk te vinden specialisten.

## "Het app-gat"
Bedrijven hebben veel meer apps nodig dan IT kan bouwen: weinig tijd en budget, papieren en complexe processen, verouderde systemen, druk vanuit de business (die steeds vaker zelf technologie financiert). Low-code platformen vullen dat gat.

## Nadelen / aandachtspunten
- Zonder [[Governance]] krijg je wildgroei aan apps (shadow IT).
- Niet alles is mogelijk; voor zeer specifieke noden blijft code nodig.
- Licenties en limieten (bv. premium connectors, API-requests).
