# User Testing (les) 👀

> Je lo-fi prototype staat. Nu test je het bij **echte gebruikers**: je kijkt **wat ze doen**, **waar ze vastlopen** en **wat ze verwachten**. Doel = **begrijpen, niet bewijzen**.

## Waarom?
Omdat **jij niet je eigen gebruiker bent**: jij weet hoe je app werkt, een nieuwe gebruiker niet.
- 🧠 ontdek waar gebruikers **écht** vastlopen;
- 👂 leer hoe mensen je flow **interpreteren**;
- 🔄 bespaar tijd door **vroeg** te corrigeren;
- 💡 input **vóór** je veel investeert in design;
- 🧭 beslissingen op basis van **gedrag**, niet aannames.

## Basisprincipes
| Principe | Betekent |
|---|---|
| 👀 gedrag > meningen | "Mooi!" zegt niets; kijk waar iemand twijfelt, terugkeert, vastloopt |
| 🧩 één taak/flow per keer | vergelijkbare resultaten |
| 💬 [[Hardop denken]] | je hoort ook **waarom** |
| ⚙️ prototype hoeft niet perfect | een ruw prototype levert al inzichten |
| 📋 noteer opvallend gedrag | verwarring, omwegen, stiltes |

## Stappenplan
### 🧱 1. Voorbereiding
1. Kies de flow en verwoord hem als een **duidelijke taak**: *"Zoek naar een smartphone en koop een iPhone 16."* (doel, geen instructies over **hoe**).
2. Schrijf **2–3 observatievragen voor jezelf** (niet voor de tester!): *"Vindt de gebruiker de filteroptie?"*, *"Gebruikt hij het winkelmandje spontaan?"*
3. Zet het prototype klaar in **Present mode** (Figma).
4. Leg kort uit wat je verwacht: *"Vertel luidop wat je denkt: wat je probeert, wat je verwacht dat er gebeurt, wat je opvalt."*
Leg dit vast in een [[Testplan]].

### 👀 2. Test uitvoeren
Typische uitspraken: *"Ik klik hier, want ik verwacht naar het productdetail te gaan."* · *"Ik weet niet wat dit icoon betekent."* · *"Ik dacht dat ik hiermee kon filteren."*
- **Grijp niet in, geef geen tips** — ook niet als het pijnlijk lang duurt.
- Noteer wat de tester **zegt en doet**, waar die **twijfelt of vastloopt**.
- Na de taak: verhelderende vragen — *"Wat had je verwacht toen je hier klikte?"*, *"Wat maakte dit duidelijk of verwarrend?"*, *"Was er iets dat je niet vond of anders verwachtte?"*

### 🧾 3. Na elke test
Bevindingen opschrijven, **concrete** verbeterpunten benoemen (structuur, flow, labels…), herhalen met de volgende taak en tester.

### 💬 4. Reflectie in groep
- 🧠 Wat leerden we over hoe gebruikers denken en handelen?
- 🪜 Welke concrete verbeterpunten?
- 💡 Welke oplossingen?
- 📋 Wat nemen we mee naar de volgende versie?
🎯 Inzichten vertalen naar **gerichte verbeteracties**.

## Hoeveel testers?
Al met **±5 testers** vind je de meeste grote problemen (Nielsen); in de opdracht test elke subgroep bij **minstens 4** personen uit andere teams.

## Veelgemaakte fouten
| Fout | Beter |
|---|---|
| sturende taak ("klik op Filter en…") | doel geven ("vind een goedkope smartphone") |
| uitleggen of verdedigen tijdens de test | zwijgen, noteren, achteraf vragen |
| vragen "vind je dit mooi?" | vragen "wat verwachtte je hier?" |
| één tester = conclusie | patronen over meerdere testers zoeken |
