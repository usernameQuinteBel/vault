# Introductie UI UX

> Eerste les: **wat** UI en UX zijn, **waarom** je dit als developer moet kunnen, en **hoe** het vak in elkaar zit (zie [[UI UX]] voor het overzicht).

> *"As a developer, you don't just build software — you build experiences."*

## UX en UI
| | UX — User Experience | UI — User Interface |
|---|---|---|
| Wat | de **ervaring** van de gebruiker: vindt die snel wat hij zoekt, begrijpt hij wat er gebeurt, voelt het logisch? | de **visuele laag**: kleuren, typografie, knoppen, spacing |
| Vraag | "Werkt het voor de gebruiker?" | "Hoe ziet het eruit en voelt het aan?" |
| Methodes | [[Gebruiksscenario]], [[User journey map]], [[User flow]], [[User testing]] | [[Visuele hiërarchie]], [[Kleursysteem]], [[Typescale]], [[Design system]] |
Ze zijn **onlosmakelijk verbonden**:
| Combinatie | Resultaat |
|---|---|
| mooie UI + slechte UX | **frustratie** (mooi, maar je raakt nergens) |
| slechte UI + goede UX | **bruikbaar maar onaantrekkelijk** |
| goede UI + goede UX | **succes** |
Mensen vinden mooie interfaces bovendien **bruikbaarder** dan ze zijn → [[Aesthetic-usability effect]]. Zie ook [[UX en UI]].

## Waarom UI/UX in 3APP?
| Reden | Uitleg |
|---|---|
| Succes van software | zonder goede UX haakt de gebruiker af, hoe goed de code ook is |
| Design telt altijd mee | elk app-project wordt (indirect) beoordeeld op de interface |
| Brug tussen code en gebruiker | UI/UX vertaalt technische functies naar een begrijpelijke ervaring |
| Samenwerken met designers | je begrijpt hun keuzes en kan met hun tools ([[Figma]]) werken |
| Arbeidsmarkt | bedrijven zoeken developers met oog voor design, gebruiksvriendelijkheid en toegankelijkheid — met AI die code schrijft ligt die lat **hoger** |

## Leerdoelen
1. Behoeften van gebruikers **analyseren** en vertalen naar een functioneel UX-concept op basis van UX-principes.
2. In **Figma** aantrekkelijke en **toegankelijke** prototypes ontwerpen op basis van een user flow en UI-principes (hiërarchie, contrast, consistentie).
3. Een ontwerp **overdraagbaar** maken aan stakeholders (ook developers) met een **design system**.

## Hoe het vak loopt
| Verwachting van de docent | Wat jij krijgt |
|---|---|
| actieve aanwezigheid (permanente evaluatie) | praktijkgerichte lessen: korte theorie + doen |
| laptop dicht tijdens theorie als je hem niet nodig hebt | coaching en feedback van docent **en** medestudenten |
| ook buiten de les kennis opdoen en opdrachten uitwerken | werkcolleges met ruimte voor vragen |
| zelf feedback geven aan anderen | contact via MS Teams (voorkeur) of e-mail |
Materiaal op **Canvas** (slides, FigJam-borden, externe bronnen). Een **Figma Education-account** is verplicht ([[Figma]], [[FigJam]]).

> *"The only way to do design is to do design."* — Alan Cooper (stop met design "leren", begin met doen).
