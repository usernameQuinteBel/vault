# Gebruikersanalyse 🕵️

> Van **gebruiksscenario** naar **journey**, **pijnpunten** en **flow**. De kernboodschap: **observeer eerst, begrijp het probleem, ontwerp daarna.**

## Drie succesverhalen, één patroon
| Product | Begon als | Wat ze zagen | Wat ze deden |
|---|---|---|---|
| **Instagram** | *Burbn*: check-ins, plannen, foto's, sociale functies | gebruikers deelden vooral **foto's**; daar kwamen likes en reacties op | bijna alles geschrapt, verder gebouwd rond foto's → ±25 000 gebruikers op dag 1 |
| **Airbnb** | 3 luchtmatrassen tijdens een volgeboekte conferentie | data toonde **waar** het misliep (New York), niet **waarom** | founders gingen bij hosts logeren → slechte foto's en listings → betere foto's, hosts geholpen |
| **Canva** | Melanie Perkins gaf les in designsoftware | studenten worstelden telkens met dezelfde complexe tools | herdacht: misschien is de software te moeilijk → eerst Fusion Books, dan Canva: **minder frictie**, niet meer features |
Gemeenschappelijk: **gedrag** (wat gebruiken mensen écht?), **context** (wat gebeurt er in hun situatie?) en **frictie** (waar lopen ze telkens vast?) — telkens **vóór** de oplossing.

## Stap 1 — Gebruikers begrijpen: het scenario
Vier vragen:
| | Vraag | Voorbeeld |
|---|---|---|
| **User** | wie? | student die een studieruimte nodig heeft |
| **Context** | wanneer/waar? | op de smartphone, tussen lessen, weinig tijd |
| **Goal** | wat wil die bereiken? | snel een geschikte ruimte reserveren |
| **Constraints** | waar moet je rekening mee houden? | beschikbaarheid, capaciteit, tijdsloten |
Samengevat in één **scenario sentence**: *"Een [user] wil [context] [goal] terwijl [constraints]."* Bv. *"Sam is onderweg naar zijn volgende les. Hij heeft binnen een uur een ruimte nodig voor groepswerk en wil op zijn smartphone snel een beschikbare ruimte voor zijn groep reserveren."* Zie [[Gebruiksscenario]].

## Stap 2 — Van aannames naar bewijs
| Methode | Hoe | Output |
|---|---|---|
| **Observe** | echt gebruik bekijken: waar twijfelt of vertraagt iemand? | concrete observaties + screenshots/notities |
| **Feedback** | reviews, supportvragen, online feedback lezen | terugkerende patronen/klachten |
| **Talk** | kort gesprek over een **recente, concrete** ervaring | context, doelen, verwachtingen |
| **Data** | bestaande data: waar haken mensen af, wat gebruiken ze vaak? | patronen op grotere schaal |
**Minimum in dit vak**: zelf het gebruik observeren + minstens één extra bron indien haalbaar. Doel: aannames **expliciet** maken en waar mogelijk vervangen door **bewijs**. Zie [[Methoden voor gebruikersonderzoek]].

## Stap 3 — Van doel naar ervaring: de user journey map
Een **user journey** = de stappen die een gebruiker doorloopt om een doel te bereiken. De **[[User journey map]]** visualiseert dat binnen één scenario: **fases, acties, verwachtingen/ervaring (emotie), [[Pijnpunt|pijnpunten]] en kansen**. Een teamtool om knelpunten te bespreken en stakeholders op één lijn te krijgen.

## Stap 4 — De user flow
Het **pad** dat een gebruiker in je app neemt om één specifiek doel te bereiken (bv. inloggen): stappen, beslissingen, interacties.
| Vorm | Betekent |
|---|---|
| ⚪ cirkel | start/eindpunt (of een andere flow) |
| ▭ pil-vorm | scherm of actie |
| ◇ diamant | beslissingspunt (ja/nee) |
| → pijl | route |
| ⇢ gestreepte pijl | alternatieve route |
Zie [[User flow]].

## Journey ≠ flow
| User journey map | User flow |
|---|---|
| de hele **ervaring**, ook buiten de app (zoeken, twijfelen, bellen) | enkel de **stappen in de app** |
| emoties, verwachtingen, pijnpunten | schermen, beslissingen, routes |
| "hoe voelt het?" | "hoe werkt het?" |
