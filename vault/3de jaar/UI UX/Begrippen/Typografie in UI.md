# Typografie in UI

> Typografie bepaalt **leesbaarheid, structuur en toon**. Kleine keuzes maken het verschil tussen amateuristisch en professioneel.

## Basisregels (uit de les)
| Regel | Waarde | Waarom |
|---|---|---|
| aantal fonts | **max. 2**, met meerdere gewichten | rust; hiërarchie komt uit grootte/gewicht |
| soort | **sans-serif** voor UI-tekst (Inter, Roboto, SF Pro); serif kan voor titels | leesbaar op schermen, ook klein |
| gewichten | bv. Regular · Medium · Semi Bold · Bold | genoeg voor een volledige hiërarchie |
| regelhoogte | **1.4–1.6×** lopende tekst, **1.1–1.3×** titels | lucht vs. compactheid |
| regellengte | **45–75 tekens** | te lang = regel kwijt, te kort = schokkerig |
| uitlijning | **links** | vast leesritme (gecentreerd enkel voor korte titels) |
| basisgrootte | **16 px** body (14 voor compacte apps) | leesbaar, standaard in browsers |

## Welk font voor een interface?
Een UI-font moet **neutraal en goed leesbaar op kleine groottes** zijn: open vormen, duidelijke onderscheiding tussen I/l/1, meerdere gewichten. Uitgesproken display-fonts (zoals het condensed *Druk* of het contrastrijke *Didone*) zijn mooi voor affiches, maar niet voor lopende UI-tekst; neutrale grotesks (Helvetica, Inter) wél.

## Typografie als systeem
Leg alles vast als **text styles** (grootte + regelhoogte + gewicht + letterspatiëring) volgens een [[Typescale]]: H1, H2, H3, Body, Small, Caption. Elke tekst in je ontwerp gebruikt een style — geen losse waarden ([[Hi-fi checklist]]).

## Toegankelijkheid
Voldoende **contrast** (4,5 : 1, [[Kleurcontrast]]), geen te dunne gewichten voor kleine tekst, tekst moet tot **200 %** kunnen schalen.

## Tools
fontpair.co (combinaties), Google Fonts, typescale.com.
