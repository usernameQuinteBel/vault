# Design system

> Een verzameling **herbruikbare componenten, stijlen en richtlijnen** die zorgt voor consistentie en schaalbaarheid. Het centrale referentiepunt voor het hele team: *"the single source of truth for design decisions."*

## Wat zit erin?
| Laag | Inhoud | Notitie |
|---|---|---|
| **Foundations** | Kleuren (primitives + tokens), typescale, spacing, grid | [[Design tokens]] · [[Typescale]] · [[Spacing system]] · [[Layout grid]] |
| **Componenten** | Knoppen, invoervelden, kaarten met al hun varianten en states | [[Component set en varianten]] |
| **Richtlijnen** | Korte gebruiksregels: wanneer gebruik je wat? | [[Design system documenteren]] |

## Design system vs. component library vs. UI kit
- **Component library**: enkel de bouwstenen (knoppen, velden…).
- **UI kit**: kant-en-klare set om mee te starten.
- **Design system**: bouwstenen **+** tokens **+** regels **+** documentatie. Het "waarom" en "wanneer", niet enkel het "wat".

## Zelf bouwen in dit vak
Je maakt een klein design system om:
- de fundamenten van visuele consistentie te leren;
- te begrijpen waarom grote systemen werken zoals ze doen (Material, Apple HIG…);
- de logica achter componenten en varianten te snappen;
- beter met [[Figma]] te leren werken.

In de praktijk start je vaak van een bestaande UI kit en pas je die aan. In een volgend project mag dat ook: dan begrijp je hoe zo'n kit werkt.
