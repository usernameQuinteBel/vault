# Testplan

> Een korte voorbereiding die je **vóór** de user tests opstelt, zodat elke sessie **op dezelfde manier** verloopt en de resultaten **vergelijkbaar** zijn.

## Wat staat erin?
| Onderdeel | Voorbeeld |
|---|---|
| **Doel van de test** | "Nagaan of gebruikers zonder hulp een studieruimte kunnen reserveren." |
| **Te testen flow(s)** | reserveren, reservatie annuleren |
| **Taak per flow** (doel, geen stappen) | "Je hebt binnen een uur een ruimte nodig voor 4 personen. Reserveer er één." |
| **Observatievragen** (voor jezelf, 2–3) | "Vindt de gebruiker de capaciteitsfilter?" · "Begrijpt hij het tijdslot-icoon?" |
| **Introductietekst** | "We testen het ontwerp, niet jou. Denk luidop…" |
| **Nabespreekvragen** | "Wat had je verwacht toen je hier klikte?" · "Wat was verwarrend?" |
| **Rollen** | wie begeleidt, wie noteert |
| **Testers** | min. 4 per subgroep, uit andere teams |
| **Wat noteer je** | gelukt/niet gelukt, tijd, twijfels, citaten, omwegen |
| **Materiaal** | prototype-link in Present mode, startscherm, notitieblad |

## Goede taken schrijven
| ❌ Sturend | ✅ Neutraal |
|---|---|
| "Klik op 'Filter' en kies 4 personen." | "Zoek een ruimte voor je groep van 4." |
| "Gebruik het winkelmandje." | "Koop een iPhone 16." |
Een taak bevat een **doel en context**, nooit het label van de knop die je wil testen.
