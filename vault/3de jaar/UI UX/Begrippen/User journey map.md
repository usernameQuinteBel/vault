# User journey map

> Een visualisatie van de **ervaring** van een gebruiker binnen **één concreet scenario**: welke fases hij doorloopt, wat hij doet, wat hij verwacht en voelt, waar het pijn doet en waar kansen liggen.

## De opbouw (rijen × kolommen)
| | Fase 1: Oriënteren | Fase 2: Zoeken | Fase 3: Reserveren | Fase 4: Na afloop |
|---|---|---|---|---|
| **Acties** | app openen tussen lessen | filteren op tijd en capaciteit | tijdslot kiezen, bevestigen | bevestiging ontvangen |
| **Verwachtingen / ervaring** | "snel zien wat vrij is" 🙂 | "waarom geen filter op aantal?" 😕 | "werkt het nu of niet?" 😟 | "oké, geregeld" 🙂 |
| **Pijnpunten** | inloggen duurt lang | geen capaciteitsfilter | geen feedback na klikken | geen herinnering |
| **Kansen** | ingelogd blijven | filter op groepsgrootte | duidelijke bevestiging | push-melding 15 min vooraf |
Bovenaan: de **persona/user** en het **scenario** (doel + context). Vaak met een **emotiecurve** over de fases.

## Waarom?
- Brengt **knelpunten en kansen** in kaart, ook **buiten** de app.
- **Teamtool**: samen bespreken en prioriteren.
- Ondersteunt **alignering** van stakeholders.

## Journey map vs. user flow
| User journey map | [[User flow]] |
|---|---|
| hele ervaring, emoties | enkel stappen in de app |
| "hoe voelt het?" | "hoe werkt het?" |

## Tips
- Eén journey = **één scenario** (anders wordt het vaag).
- Baseer je op **bewijs** (observaties, reviews), niet op aannames.
- Elke **pijnpunt** krijgt een **kans** → input voor je ontwerp.
