# Wireframe

> Een **schematische weergave van de structuur** van een scherm: wat staat waar, wat is belangrijk, hoe navigeer je. Bedoeld om indeling, hiërarchie en navigatie vast te leggen **vóór** je gaat designen. Kan op papier of digitaal.

## Waarom eerst (lo-fi) wireframen?
- ✏️ **Goedkoop itereren**: fouten maken mag en kost bijna niets.
- 💬 **Focus op inhoud & flow**: wat moet de gebruiker kunnen doen?
- ⏱️ **Snelheid**: binnen minuten een idee testen.
- 🧭 **Vroege feedback**: je steekt geen uren in visuele details die misschien weg moeten.
- 🧠 **Denken in hiërarchie**: wat is echt belangrijk op dit scherm?

## Best practices
| Regel | Waarom |
|---|---|
| ⚪ Grijstinten, denk in blokken | Kleur leidt af van structuur |
| 🧭 Max. 2 lettertypes, enkel voor hiërarchie | Typografie komt later (zie [[Typescale]]) |
| ⬛ Rechthoeken (met kruis) voor media | Beeld aanduiden, niet uitwerken |
| 🏷️ Betekenisvolle tekst ("Login", "Bestellen") | Lorem ipsum verbergt of labels duidelijk zijn |
| 🚫 Geen animaties | Afleiding |
| 💬 Noteer intentie voor je team | Wat moet er gebeuren als het niet uitgewerkt is? |
| 🔁 Itereer snel | Meerdere ruwe versies = meer inzicht |

🎯 **Focus op structuur en interactie, niet op vormgeving.**
